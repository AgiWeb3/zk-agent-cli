## Summary

- This RC keeps the same validated zkSync-native execution baseline, but it
  makes the public shell shorter and more legible. The release tightens the
  first-screen CLI story around one shortest success path, one clearer surface
  chooser, and three bounded proof paths. It also keeps `suite`, wallet
  handoff guidance, docs, and release validation aligned around the same
  question-first product narrative instead of leaking more operator-only
  structure into the public entry surface.

## Highlights

- Top-level `zk-agent --help` now starts with the shortest happy path, then
  routes users explicitly across `start`, `next`, `workflow pay`, `suite`,
  `payment`, and `relay`, instead of presenting the full surface in a flatter
  operator-first shape.
- The packaged post-flagship surface is now easier to explain: `suite`,
  `suite` handoff summaries, help text, and docs all reinforce the same
  question-first choices, bounded proof routes, and broader-surface handoff.
- Agent Pay remains local-first, but its public proof route is easier to demo
  and easier to discover from the root help and packaged guidance.
- Release and state docs were tightened again: version pointers, changelog,
  stage-aware release checklist wording, and current review/readback metadata
  are aligned for this RC cut.
- This release adds packaging and narrative clarity, not new protocol breadth:
  hosted approval remains the supported single-host baseline and broader DeFi
  expansion is still deferred.

## Known Limits

- This is still an `rc`, not `1.0.0`.
- Hosted approval remains the documented single-host operated baseline; this
  release does not claim a managed or multi-tenant relay service.
- Agent Pay still stops at the local-first request and follow-up layer; it is
  not yet a hosted control plane or multi-tenant payment platform.
- The public shell is tighter than the previous RC, but onboarding is still
  not yet as market-ready as the final `1.0.0` bar.

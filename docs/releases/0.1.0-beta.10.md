## Summary

- This release productizes the local-first operator shell around
  `setup -> doctor/next -> wallet create|reapprove -> workflow pay`, and
  tightens the repo-owned release contract with versioned release notes,
  changelog synchronization, and a git-derived draft-input flow.

## Highlights

- `zk-agent doctor`, `zk-agent setup`, and top-level `zk-agent next` now share
  one tested `onboardingSummary` contract, so operators and agent harnesses
  can recover local-first state without scraping help text.
- Relay-backed approval is framed as an explicit operated product boundary
  instead of an implicit prototype: the repo now documents the current
  supportable hosted mode as a single-host, same-origin, filesystem-backed
  baseline.
- Workflow, wallet, relay, and discovery surfaces were tightened around one
  clearer product shell, with help text, JSON output, and follow-up commands
  aligned across the flagship `workflow pay` path.
- Release automation is stronger than in earlier beta cuts:
  `release:sync-version` now maintains `CHANGELOG.md` plus versioned release
  notes, and `release:draft-notes` can seed the public note from a chosen git
  range before the final editor pass.

## Known Limits

- This release remains `beta`; it should not be presented as `rc` or `1.0.0`.
- Hosted approval is supportable today only on the documented operated
  baseline: one relay process, one host, one persistent local filesystem view,
  and the connector UI served from the same public origin.
- Broader DeFi breadth and broader ecosystem parity remain backlog items; the
  public promise is still centered on the local-first wallet lifecycle,
  hosted approval, discovery, and the flagship `workflow pay` operator path.

## Summary

- This RC promotes `zk-agent-cli` out of the beta gate and into the first
  release-candidate cut. The main change is not new chain mechanics; it is
  that the operator contract is now explicit and defensible: hosted approval
  has repeated public evidence plus deterministic recovery evidence, the
  release flow has one machine gate plus one review artifact, and the public
  machine-readable surfaces are now treated as compatibility boundaries.

## Highlights

- `pnpm validate:rc` now executes the deterministic hosted recovery drill for
  real, saves a structured report under `~/.zk-agent/reports/hosted-recovery/`,
  and carries that evidence into the RC machine-gate summary.
- `pnpm review:rc` now records both the public hosted operated-baseline
  evidence and the local hosted-recovery evidence in one repo-tracked RC
  review artifact.
- Release tooling now understands the RC stage explicitly:
  `0.1.0-rc.0` uses the `rc` publish tag by default, while release metadata can
  describe `beta`, `rc`, and `latest` together instead of forcing every cut
  into a beta-only shape.
- The public release-stage docs, README, plans, and project state now agree
  that the `beta -> rc` gate is closed and that the remaining stage gap is
  `rc -> 1.0.0`.

## Known Limits

- This release is `rc`, not `1.0.0`; do not present it as a fully stabilized
  final product.
- Hosted approval is still supported only on the documented single-host,
  filesystem-backed operated baseline.
- Broader DeFi breadth remains deferred; the current public promise is still
  centered on the wallet lifecycle, hosted approval, discovery/defaults,
  funding readiness, paymaster readiness, and flagship `workflow pay`.

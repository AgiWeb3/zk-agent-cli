## Summary

- This RC adds the first real Agent Pay surface on top of the existing zkSync
  operator runtime. Operators can now create, inspect, list, update, and
  remove local-first payment request records, while the underlying payment
  linkage moves onto stable wallet identifiers and the payment JSON contract
  becomes explicit enough for harness consumption. This RC also adds the first
  append-only payment history baseline so payment status is no longer only the
  latest snapshot.

## Highlights

- `zk-agent payment` is now a first-class CLI surface for local-first payment
  request lifecycle management, instead of forcing payment intent to live only
  inside workflow or send commands.
- A dedicated `packages/agent-pay` workspace package now owns payment request
  models, storage, service orchestration, and execution-plan shaping, which
  keeps payment semantics out of CLI command glue.
- Wallet records now carry stable `walletId` values, and Agent Pay records use
  that identifier so wallet rename flows no longer rely only on mutable wallet
  names.
- Payment outputs now expose an explicit `executionPlan` contract for native
  transfer versus ERC-20 transfer paths, including wallet, chain, paymaster,
  asset, and command follow-up fields.
- Payment request records now keep an append-only `history[]` baseline with
  legacy local records migrated forward on read, which improves auditability
  and prepares the next Agent Pay platform layer.

## Known Limits

- This remains an `rc`, not `1.0.0`.
- Agent Pay is still a local-first request and settlement primitive, not yet a
  full platform API with quotes, reconciliation, reporting, or hosted control
  plane surfaces.
- Hosted approval remains scoped to the documented single-host operated
  baseline.
- Broad DeFi expansion remains deferred; the public promise is still centered
  on zkSync wallet lifecycle, hosted approval, flagship `workflow pay`, and
  the emerging Agent Pay surface.
